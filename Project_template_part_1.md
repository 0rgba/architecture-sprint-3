# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут управлять отоплением в доме
- Система поддерживает синхронные вызовы для установки температуры от сервера к датчику
- Подключение датчика только с выездом специалиста

**Мониторинг температуры:**

- Пользователи могут проверять температуру с датчиков через веб-интерфейс
- Система поддерживает синхронный вызов на получение данных о температуре через запрос от сервера к датчику

### 2. Анализ архитектуры монолитного приложения

Текущее приложение - монолит на Java. В качестве СУБД используется PostgresSQL. Используются только синхронные вызовы между различными частями приложения. Масштабируемость ограничена, деплой требует остановки всего приложения. Микросервисов, реактивности и асинхронности нет.

### 3. Определение доменов и границы контекстов

- Домен: работа с учётной записью
  - Контекст: создание учётной записи
  - Контекст: управление учётной записью
- Домен: управление устройствами
  - Поддомен: настройка (добавление/удаление) устройств
    - Контекст: подключение нового устройства к учётной записи
    - Контекст: группировка устройств (здания/квартиры/комнаты)
  - Поддомен: HelpDesk
    - Контекст: работа с обращениями пользователей
- Домен: управление, мониторинг и сценарии
  - Контекст: управление мониторингом (настройка уведомлений о превышении предельных значений)
  - Контекст: управление сценариями (выполнение определённых действий в зависимости от условий)
  - Контекст: ручное управление устройствами
- Домен: телеметрия
  - Контекст: просмотр текущих показателей
  - Контекст: просмотр исторических данных и событий по конкретному датчику

### **4. Проблемы монолитного решения**

Проблемы, описанные в условии задания, вызваны по бОльшей части не тем, что приложение монолитное, а неправильной реализацией функционала. На описанном объёме функциональных возможностей можно было бы реализовать всё и в рамках монолита без описанных проблем. Но для дальшейншей реализации расширенного фукнционала было бы удобнее разделить проект на микросервисы.
